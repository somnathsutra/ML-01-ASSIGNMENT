What should an editor review first?

A ranking signal analysis of five observable search signals, a transparent review rule, and a client-held-out Random Forest.

2×precision at the top 50 compared with the transparent baseline on held-out clients.
01 / PROBLEM

The decision is the product.

Editors have limited time. The practical question is not “what does the search algorithm want?” It is which content items deserve a closer look when visibility, clicks, CTR, position, and activity move together.

This paper turns that question into a ranked review queue. The queue is a decision-support instrument: a person checks query mix, snippet fit, and measurement quality before making any content change.

02 / DATA

The source is FlyRank’s pseudonymized fact_content_daily_performance table, restricted to month=2026-03. Features use March 1–15. The observed movement proxy uses March 16–31, and incomplete second-half histories are excluded from model evaluation.

The five features are first-half impressions, clicks, CTR, average position, and active impression days. Client and content hashes are grouping context only. Future-window values, trend fields, product decisions, raw queries, URLs, client names, and credentials are excluded.

03 / METHOD

Simple enough to audit.

Target proxy

A content item is marked as declining when second-half impressions per day are below 80% of first-half impressions per day. This is an observed movement proxy, not a causal label.

Validation

GroupShuffleSplit holds out 11 clients. The model and baseline rank the same test rows. The seed is 42.

Baseline

Volume points are combined with a position-aware low-CTR screen. Each queue item gets one reason code and one action label.

Leakage check

An exact label copy scored 1.000. Removing it produced the honest grouped score of 0.604, proving the attack can expose contamination.

Interpretation: the model improves the top of the queue, but it is not a complete detector. Average position, impressions, active days, and CTR were the strongest feature-importance signals; those are diagnostic clues, not causal explanations.
05 / LIMITS

What this cannot prove.

This is one March mid-panel slice from an unbalanced client panel. The result measures out-of-sample ranking performance for this proxy and this period. It does not prove that changing a title, snippet, or page will improve rankings, and it does not model or predict Google’s algorithm.

False negatives outnumber false positives, so human review remains necessary. Future-month stability, richer query-mix signals, and a broader time-aware evaluation are the next tests.

06 / ACTIONS

A queue for tomorrow morning.

  1. Review high-volume, low-CTR pages first. Check query mix and title/snippet alignment before editing.
  2. Use volume as an opportunity filter. High impressions show measurable opportunity, not poor content by themselves.
  3. Investigate zero-click anomalies. They may indicate query intent, measurement, or snippet issues.
  4. Use the Random Forest as a second ranking aid. It improves held-out precision, but its errors require a human decision.
Confidence is directional and moderate for queue prioritization, low for future improvement, and zero for causal claims.
